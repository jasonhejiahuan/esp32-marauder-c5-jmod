# 设备概览、蓝牙与控制台

2026-10-10，Waveshare ESP32-C5-WIFI6-KIT-N32R8-U 专用修改版。

## 页面

原「概览」更名「WLAN 概览」，其原有 AP / STA / Beacon、手动控制提示及停止入口保留。新的「概览」显示真实芯片温度、CPU 频率、运行时间、内部堆、PSRAM、内部文件系统、设置 SPIFFS 和应用分区；温度有短期曲线。不能取得的数值不填估计值。

芯片温度是片内温度，不是室温；传感器配置范围为 -10 至 80°C，失败返回 null。内存百分比是已使用容量，不是 CPU 使用率。复位原因、芯片修订、物理 Flash 与驱动地址窗口分别报告。应用长度只在启动时读取并缓存，避免在每次查询中校验整个镜像。CPU 使用率、电池电量、电流没有可靠测量链路，本次不显示。

C5 硬件支持 Wi-Fi、BLE、IEEE 802.15.4。概览中的 802.15.4 是硬件能力，未声称现有固件已启用 Thread/Zigbee 栈；蓝牙页使用本构建实际可用的 BLE，非经典蓝牙。

## USB 查询与多端

- 固件 `deviceinfo [--machine <transaction-id>]` 只应答一次，不启用固件自主上报。
- 浏览器使用原有 SSE 缓存推送。可见设备概览请求 2 秒一次，其他可见页 15 秒一次；浏览器标签隐藏时不需要采样。
- 每个浏览器每 10 秒通过本机 HTTP 续租，租期 25 秒；正常关闭时释放。多个客户端合并为一份需求，采用当前所需的最高频率。
- 设置中的「设备概览」是服务端全局开关，持久保存到 `.desk-settings.json`。关闭后所有客户端的自动设备指标查询停止、侧栏入口隐藏。已进入 USB 的在途响应不能撤回；待其结束后不会再有指标相关 USB 字节。HTTP 心跳和 SSE 不等于 USB 查询。
- 没有客户端时不采样，租约异常丢失最长 25 秒后过期。CLI 手动控制期间也暂停自动采样，避免向手动命令序列插入查询；结束手动控制后恢复。
- 一个指标请求在途时不再追加；超时后降速重试。用户命令队列优先，仍由唯一串口线程写入。
- 新构建的 C5 HWCDC TX 缓冲从默认 256 B 增到 2048 B，自动 BLE 输出检查剩余容量并限量发送。没有把波特率数字当成 USB 带宽，也没有改变 USB 协议。

## 蓝牙

CLI：`bleobserve start|stop|status|clear`。命令及语法已加入固件 help，会进入现有动态补全。`stopscan` 同样停止该被动发现模式。

被动接收广播；不发送 Scan Request、不配对、不连接设备。不执行 BLE spam、跟踪器鸣响等行为。WLAN 和新 BLE 采集互斥，必须先停止当前任务；原先各独立 WLAN 扫描逻辑不变。

页面显示广播地址、广播报告数、RSSI 曲线、可连接标记、地址类型、名称、广播中的服务 UUID、Company ID、TX Power、Appearance 和原始广播十六进制。名称/服务如果只在 Scan Response 或 GATT 中提供，被动广播不一定能取得；空白不代表设备没有此功能。地址随机化意味着一个物理设备可能贡献多个地址，不用地址数量冒充物理设备数量。

回调只把记录加入 24 项有界队列；主循环使用 PSRAM 中 256 项表，最多 16 次探测，每地址最多每秒报告一次，每 200 ms 最多输出 3 条。原始广播最多输出前 96 字节、名称前 32 字节、前三个广播服务 UUID；截断有标记。设备表或队列溢出显示计数。前端保留最多 1000 个地址；累计 20 秒有效扫描时间未见后灰显，可隐藏；状态中断或停止不继续老化，不强行删除展开项。导出是本机 JSON。停止后查看历史不查询硬件。

## 控制台布局

浮窗为右侧工作区 84% 宽、78% 高，面积约 65.5%，接近请求的 2/3；1512 × 900 CSS 视口时约 1089 × 702。放大后 x=216，宽=1296、高=900，仍保留左侧导航。小屏自适应，无浏览器 Fullscreen API。

保留现有命令预测、二级预测、Tab、上下键、简短注释及语法提示。Esc 先收起预测，再关闭控制台；关闭浮窗不停止手动任务，状态和结束入口在 WLAN 概览中。

14 英寸 M3 Pro/Max 官方面板分辨率为 3024 × 1964；1512 × 900 是扣除窗口装饰后的常见测试视口，不是声称所有用户的固定逻辑分辨率。该比例是经过实测的设计选择，没有客观唯一的“最佳比例”。
