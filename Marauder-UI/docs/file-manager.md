# 文件管理与浮动控制台

2026-10-11 · `1.18.0-jmod1.1` · Waveshare C5 专用构建，能力 `files-v1`、`files-delete-v1`。

文件页只访问开发板的内部 LittleFS 应用存储，不访问配置 SPIFFS 或 NVS。目录按需读取，每页最多 20 项，无自动 USB 轮询。支持下载、创建目录、重命名，以及移动至回收站和恢复。回收站仍占用 Flash。回收站内支持永久删除文件/文件夹，也可以清空整个回收站；没有覆盖上传或格式化按钮。采集期间禁用文件操作，避免与抓包写入竞争。

下载由 Python 后端管理生命周期，网页只启动一次传输并显示进度；刷新不会重启传输。Host_Connection 使用二进制记录、字节额度、偏移/长度及整文件 SHA-256 校验；旧固件内部使用文本分块和第二遍整文件校验。取消停止新请求、释放文件句柄并仅删除该传输的临时文件。成功后通过普通 HTTP 下载到浏览器；失败不提供未验证文件。细节见 [Host_Connection](Host_Connection.md)。

重命名和回收站移动不覆盖已有同名内容；恢复返回原路径。所有路径限定在该卷，拒绝父目录跳转、控制字符和超长路径。命令请求使用本机服务原有令牌、来源校验和串行队列。

控制台入口位于右下角。悬停展开，离开后收起；点击入口或固定按钮可保持展开。在内部输入、选择文本或最大化时不自动关闭。原命令预测、逐级语法、Tab 与方向键继续可用。小屏用点击打开，最大化只占右侧工作区。

蓝牙的“隐藏掉线设备”单独保存。只在有效 BLE 扫描状态持续、报告间隔不超过 5 秒、丢弃和表满计数未增加的时段累计未见时间；累计 20 秒未见后标为离线。停止、状态丢失或拥塞期间冻结判断。关闭隐藏时灰显，打开时从列表、统计和导出排除。展开或聚焦的详情延后到收起时删除，不随 RSSI 改变重排行。无线接收缺失并不等于确认设备关机。

永久删除仅接受 `/.trash/` 下的路径。普通目录仍使用“移至回收站”，不新增绕过回收站的删除入口。“清空回收站”总是清空整个回收站（包括子目录），保留 `/.trash` 根目录；缺失/空回收站视为已清空。确认框默认聚焦“取消”，Escape 取消；确认前不发出删除请求。后端要求 `confirm: true`，并检查 `files-delete-v1`。旧固件隐藏删除入口，后端也会拒绝不支持的请求。

CLI：`file delete <transaction> <hex-path>`、`file emptytrash <transaction> 2f2e7472617368`。CLI 命令本身就是明确的删除请求，不再额外弹出交互确认；请先核对路径。Host_Connection 使用 FILE_OP 子操作 8/9，和 CLI 调用同一个 StorageService。所有操作保留存储挂载、路径保护、扫描/BLE/传输互斥检查；双 USB 不放宽限制。

删除是文件系统级 unlink/rmdir，不是 Flash 安全擦除。目录使用迭代遍历，无递归栈增长、不在内存积攒整个目录；一次最多删除 4096 项，在文件系统调用之间检查 10 秒预算并让出执行时间。不会移动/格式化其他卷。已删除的子项无法回滚；I/O 错误、数量或时间上限会明确报告部分完成。页面随后刷新目录，不自动重复删除。确认超时属于结果未知，也要求刷新后重新确认；会话内继续使用 Host_Connection 的有界请求去重，不承诺跨重启恰好一次。

后端删除请求最多排队18秒。到执行时仍未开始且已过期的请求会被丢弃，避免 HTTP 超时后迟到执行；已经开始的操作超时仍按结果未知处理。
